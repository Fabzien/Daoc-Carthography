# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A "Google Maps"-style interactive web map of the Dark Age of Camelot MMORPG world: one map per realm and expansion, with toggleable layers for zones, dungeon entrances, horse/boat routes, NPCs, mobs and bind points generated from the Dawn of Light server emulator's database. It's a Vite + React 19 + TypeScript app using react-leaflet 5 and Zustand. It's fully static: no backend or external API. It's deployed to GitHub Pages (https://fabzien.github.io/Daoc-Carthography/) on every push to `master`.

## Commands

Requires Node.js 22.18+.

```bash
npm install
npm run dev          # dev server on http://localhost:3000
npm run build        # tsc -b, then production build into dist/
npm run lint         # ESLint (flat config, eslint.config.js)
npm run typecheck
npm test             # Vitest in watch mode
npx vitest run src/data/regions.test.ts   # single run of one file
npm run import-dol   # regenerate public/data/ (-- --release <n> | -- --data <dir>)
npm run import-cartographe   # regenerate the Cartographe-based tiles (zone mosaics and plans)
npm run import-camelotinsider # dungeon zone-map tiles and Jordheim's drawing, from Camelot Insider
```

TypeScript is pinned to 6.0.x because typescript-eslint doesn't support TS 7 yet.

## Architecture

**Map and coordinates.** [src/map/MapView.tsx](src/map/MapView.tsx) renders one `MapContainer` with `CRS.Simple`, so coordinates are plain `[lat, lng]` pixel-space values, not geographic ones. They're mostly negative lat and positive lng, for example `[-83, 80.5]`. It shows one `TileLayer` for the current region, from tiles in `public/maps/…/tiles/{z}/{x}/{y}.png` (the original seven maps are pre-rendered at zoom 0–7, gdal2tiles-style; the others are generated by `npm run import-cartographe`). The tiles account for nearly all of the ~70k files in the repo.

**Regions and calibration.** [src/data/regions.ts](src/data/regions.ts) is the single source of truth: each map has a `name` (store key and `public/data/<name>.json` file name), `label`, `group` (map picker section), tile URL and `maxNativeZoom`, and an optional `dol` calibration `{ region, scale, offset }` that `toMap()` uses to turn DOL game coordinates into map coordinates (`lng = X/scale + offset[0]`, `lat = -(Y/scale + offset[1])`). Maps without `dol` are shown without DOL data. Three kinds of maps:
- the original seven (pre-rendered tiles), calibrated by hand against zone outlines, dungeon entrances and terrain (Midgard-SI is drawn at double scale); `regions.test.ts` pins them to reference points;
- zone mosaics (`drawnZones`): Atlantis (three realm regions sharing tiles), Ruins of Atlantis, housing, battlegrounds. Built from DAoC Cartographe zone maps placed at their DOL zone offsets, so the offset follows from the top-left zone (a zone offset unit is 4 map units) with no fitting;
- dungeon maps, each one image as a 256-unit map with no zones: mostly the game's zone maps from Camelot Insider (`zoneMap`, via `zoneMap()`; 1000 px images resampled to 1024 px, native zoom 2), and DAoC Cartographe floor plans (`plan`, via `plan()`) where Camelot Insider has none (Summoner's Hall, Celestius, Great Pyramid, Cetus' Pit) or where its map can't be calibrated (Muire Tomb and Passage of Conflict are annotated community maps, City of Aerus has a sky background). Their `fit` (game units per pixel, game X/Y of the top-left pixel; for zone maps, in pixels of the image resized to 512 px) was found offline by FFT cross-correlation of the region's main group of mob positions with the map's floor pixels (not near-black), constrained by mob vs map extents, then checked by overlaying mobs and exits on each map. Maps whose fit looked wrong or that have too few mobs have no `fit` but a `dolRegion`, so entrances still lead to them (Tur Suil, Veil Rift, Crystal Cave, Deep Volcanus, and Albion's and Midgard's Abandoned Mines, whose DOL positions don't fit the map the three share). Camelot Insider only has the Midgard copies of the Atlantis dungeons, so those maps use the Midgard regions; entrances from the other copies find them by name.
- drawn capitals (`drawnCities`, via `drawnCity()`): Camelot (region 10), Tir na Nog (201) and Jordheim (101) are separate DOL regions, drawn on their realm's classic map as the game's zone map filling a zone square (the zone maps on https://camelotinsider.github.io match the original Albion/Hibernia tiles pixel for pixel; Jordheim was missing from Midgard's and is added by `npm run import-camelotinsider`). DOL's coordinates for these cities are about 6 times smaller than the drawing (the cities fit in ~10k game units), with the same layout: each capital's calibration was fitted offline (FFT) between its DOL positions and the drawing's silhouette at zoom 4, and the city exits land on the gates drawn on the walls (checked for all three). That calibration places the city's NPCs on the map and gives `/loc` inside its square. Don't mistake the scale gap for a different layout: the DAoC Cartographe city plans do show an older layout, and fitting DOL NPCs onto them looked wrong.

**Data pipeline.** The map shows data from the Dawn of Light (DOLSharp) server emulator's public database, [Eve-of-Darkness/db-public](https://github.com/Eve-of-Darkness/db-public). `npm run import-dol` ([scripts/import-dol.ts](scripts/import-dol.ts), run directly by Node's type stripping, hence `.ts` import extensions in `scripts/`) downloads a release's JSON tables into `.cache/db-public/<release>/` and writes `public/data/<region>.json` (committed, `RegionData` in [src/data/types.ts](src/data/types.ts)). The pure logic is in [scripts/dol/transform.ts](scripts/dol/transform.ts):
- zones come from the `Zones` table (offsets in units of 8192); only zones drawn on the tiles are kept, and every other entity must fall inside one of them;
- `Mob` rows with realm 0, no service ClassType and no PEACE flag are mobs (level from `NpcTemplate` when the spawn has none); the rest are NPCs, classified by ClassType (`npcKind`);
- notable mobs get a tier as the mob tuple's 5th value (`mobTier`): 2 = epic encounter, from the hand-kept `EPIC_ENCOUNTERS` list (DOL doesn't mark them; only the three realm dragons have their own ClassType; a listed name also matches "… <name>" variants like Myrddraxis's heads); 1 = named boss: capitalized name with a single spawn in the whole database, level 65+ and AggroLevel > 0 (which drops quest and event NPCs). Add missed epics to `EPIC_ENCOUNTERS`;
- routes are `PathPoints` paths starting within 1000 units of a stable/boat master (how DOL's `GameStableMaster` links tickets to paths), minus guard patrols (`patrol`/`guard` in the path id). Each keeps its `master` (name, position `from`) and destination `to`: the town of the master standing at the path's end (towns are named by the `HS_<town>_<destination>` ids of the routes leaving from them), else read from the path id (`routeDestination`, which drops the handler's name ending "…ticket to <place> <handler>");
- entrances are `ZonePoint` rows leading to another known region, named after it, with a `target` map (matched by DOL region id, else by region name: the Atlantis dungeons only have their Albion copy) and the arrival point on it when that map is calibrated;
- `gameZones` lists every zone of the region in game units, to turn coordinates into zone-relative `/loc` ones;
- floor plans have no zones (the DOL zone square means nothing on a plan): entities are kept when they fall on the plan;
- a drawn capital's entities, bind points and zone points are placed with its calibration and kept inside its square (also a `Zone`); entrances to it lead to the host map (`mapForRegion` returns the host and the city's calibration). Its `GameZone` has an `area` (square + calibration), so `locate()` and coordinate search use the city's coordinates there.

**Camelot Insider maps.** `npm run import-camelotinsider` ([scripts/import-camelotinsider.ts](scripts/import-camelotinsider.ts)) downloads zone maps (JPEG, cached in `.cache/camelotinsider/`; missing ones come back as HTML pages and fail). For `zoneMap` regions it resamples the image to the native zoom and writes the region's tiles (`writeTiles` in `scripts/cartographe/tiles.ts`, shared with import-cartographe); for capitals missing from the classic tiles (Jordheim) it draws the zone map into the host map's existing tiles inside the city's square, for every zoom (`drawScaled`: area average when shrinking, bilinear when enlarging). Rerun it after anything that rewrites those tiles.

**Map tiles.** `npm run import-cartographe` ([scripts/import-cartographe.ts](scripts/import-cartographe.ts)) downloads DAoC Cartographe 2.52 from the Wayback Machine (sha256-checked, cached in `.cache/daoc-cartographe/`), decodes its 8-bit BMPs, clears the gray background from the image border, and writes tiles for zoom 0..maxNativeZoom (raster helpers in `scripts/cartographe/raster.ts`). It regenerates every tile folder it owns; the Vite dev server can then serve stale `index.html` for new tiles until restarted.

**Front end.** [src/data/regionData.ts](src/data/regionData.ts) fetches the current region's file once (cached promise) and `useRegionData()` reads it with React 19 `use()` inside `Suspense`; `useSearchIndex()` builds the search index once per region.
- [src/store.ts](src/store.ts) (Zustand) holds the UI state: `region`, visible `layers`, search `query`, mob `levels` filter, and the `selected` result. Setting a level filter turns the mobs layer on.
- [src/search.ts](src/search.ts) is the pure search logic: `buildIndex()` groups entities by name (a mob name has many spawns) into `SearchResult`s with every position; `search()` filters by name/title and level.
- [src/ui/](src/ui/) is the Google Maps-like chrome outside the map: `SearchPanel` (search box, layer chips, level filter, results, place card) and `RegionSwitcher` (bottom-left map picker using each map's zoom-0 tile as thumbnail). `kinds.ts` holds shared colors and labels.
- [src/map/MapView.tsx](src/map/MapView.tsx) renders one `TileLayer` for the store's region (no Leaflet layers control) and the overlays in [src/map/overlays/](src/map/overlays/) whose layer is on. Zones have no layer (the cursor readout names the zone); they still frame the map, appear in search and back `/loc`. `FitRegion` frames the drawn map on region change; `SelectionController` flies to the selection and clears it on a map click.
- When the NPCs layer is on, `NpcKindFilter` in the search panel is the legend of NPC colors (`NPC_KINDS`, with counts from `npcKindCounts`) and a filter: each chip hides or shows a kind on the map (store `hiddenNpcKinds`, applied by `NpcsOverlay`; search results are not filtered).
- Stable masters: search results of NPCs carry the routes departing from where they stand (`routes`). Selecting one, or a route (`routeResult`, also on click on the routes layer), makes `SelectionOverlay` draw the routes bold with a permanent destination label, and `SelectionController` frames them; the master's card lists them with their travel mode (`routeTravel`: horse, dragonfly or boat), and a route's card links back to its master.
- `BossesOverlay` (layer "Bosses", on by default) draws tiered mobs as badges (`bossBadgeHtml`: crown for epics, skull for named bosses) through `IconMarkers`, never clustered; `MobsOverlay` skips them while that layer is on. Search results carry the tier (`describe()` says "Epic encounter"/"Named boss").
- Up to zoom 3, `MobsOverlay` groups the (filtered) mobs into 48px grid cells (`clusterByGrid` in [src/map/cluster.ts](src/map/cluster.ts)) and draws groups as count bubbles (`ClusterMarkers`, colored by average level; a click zooms onto the group); lone mobs stay dots. Beyond zoom 3, every mob is drawn.
- Badges ([src/ui/badges.ts](src/ui/badges.ts)) are colored shapes with a white Lucide pictogram, as HTML for Leaflet div icons and the legend. From zoom 3, `NpcsOverlay` draws NPCs as round badges (`npcBadgeHtml`; `public/images/horse.png` for stable masters since Lucide has no horse) through `IconMarkers`, which makes DOM div-icon markers; below zoom 3 they are canvas dots. The NPC legend chips show the same badges. DOM markers are fine for the ~800 NPCs of a map, not for mobs. Entrances are near-black rounded-square door badges (`entranceBadgeHtml`), faded when they lead to no map.
- Mobs, NPCs and bind points use `CircleMarkers`, which builds Leaflet circle markers imperatively on the canvas renderer (`preferCanvas`) because there are up to ~16k per region. Clicking one selects its search result by id (`useSelectById`); markers set `bubblingMouseEvents: false` so the map click doesn't clear it. The mobs overlay is narrowed by the query and level filter.
- Entrances with a `target` open that map on click (`useEnter` → store `enter()`, which selects the arrival point; `FitRegion` then yields to `SelectionController`).
- [src/coords.ts](src/coords.ts): `locate()` (game coordinates, zone and `/loc` of a map point, via `toGame()`), `parseCoordinates()` and `coordinateResults()` for coordinates typed in the search box. `CursorLocation` in `MapView.tsx` shows the position under the cursor. Enter in the search box selects the first result (store `submits`).
- `AppFooter` (bottom center) shows the app version and build commit (`__APP_VERSION__` from package.json and `__APP_COMMIT__` from `git rev-parse`, injected by `define` in vite.config.ts, typed in `src/globals.d.ts`; restart the dev server after changing them), the DOL release of the current map's data, and a disclaimer that positions may be inaccurate.
- `SelectionOverlay` draws highlights in its own `selection` pane, above the marker pane (z-index 620 vs 600) so icon markers don't hide them. That pane's canvas covers the whole map, so it has `pointer-events: none`; without it, nothing below receives hover or clicks.

**Deployment.** `.github/workflows/deploy.yml` builds and publishes to GitHub Pages on pushes to `master` (lint, tests, build with `BASE_PATH` from `actions/configure-pages`); `ci.yml` runs the same checks on other branches and PRs. The site is served under `/Daoc-Carthography/`: Vite's `base` comes from `BASE_PATH` (default `/`), and every URL of a `public/` file (tiles, data, thumbnails, images) must go through `publicUrl()` ([src/publicUrl.ts](src/publicUrl.ts)); `regions.ts` keeps root-relative paths. Check with `BASE_PATH=/Daoc-Carthography/ npm run build && npx vite preview`.

**Leaflet setup.** Leaflet CSS is imported from the package in `main.tsx`. No marker uses Leaflet's default icon (entrances have their own, NPCs and mobs use div icons or canvas), so the default icon path, which breaks under bundlers, isn't configured.

**Checking calibration.** The in-game coordinates under the cursor (`CursorLocation`) and coordinate search are the way to check a map's calibration.

## Known gaps

- Frontiers calibration comes only from the map's bounding box (routes do follow its rivers); the others are cross-checked by several methods.
- Search covers the current map only.

## Improvement ideas

Backlog of suggested improvements, roughly by priority. Remove an item once it's done.

**Deployment and quality**
- Size: the deployed site is ~840 MB (71k files) against GitHub Pages' 1 GB limit, almost all PNG tiles. Before adding many maps, switch tiles to JPEG/WebP.
- Licensing: the DAoC Cartographe and Camelot Insider maps come without a license (Cartographe is freeware "for private use"); publishing them is the owner's call.
- e2e tests: move the Playwright scenarios used during development (search, selection, map switch, entrances, coordinates, stable routes) into the repo and CI.

**Google Maps-like experience**
- Shareable URLs: map, query and selection in the URL (`?map=Thidranki&q=wolf`); a reload currently loses everything.
- Search across all maps, not only the current one (global index, jump to the map of a result).

**Game content**
- Mob con colors relative to the player's level (gray/green/blue/yellow/orange/red/purple), like the original Cartographe.
- Decode DAoC Cartographe's community annotations (`database/Francais/master_daoc.loc` in the archive, zlib-compressed, ~1.5 MB, in French): quests, spots, tips.
- Dungeons: split floors by mob Z (Darkness Falls, Spindelhalla); calibrate Treibh Caillte, Tur Suil and Sobekite Eternal with a manual two-point tool; maps for unlinked entrance targets (Labyrinth, Abandoned Mines, Demon's Breach…).

**Freeshard**
- Import from a DOL server's own database (MySQL/SQLite) instead of db-public, so the map shows a freeshard's content (the README's original goal).

**Smaller**
- Mobile layout: the search panel and map picker take too much room on small screens.
- Check the zone-relative `/loc` convention against a real in-game `/loc`.
